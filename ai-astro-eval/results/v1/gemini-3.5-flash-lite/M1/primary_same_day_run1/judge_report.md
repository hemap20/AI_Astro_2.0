## Cross-Session Synthesis (all 3 sessions)

**Decision rule verdict:** `needs_fix`

The decision rule specifies that the test passes if a promise made in session 1 is surfaced and resolved in session 2 or session 3's opening without the user having to force it. In this run, the astrologer promised to talk about the partner's unique nature in Session 1, but in Session 2, the user had to explicitly ask ('Pichli baar aapne kuch bolna tha?'). Again in Session 3, the user had to call out the astrologer ('Aapne kaha tha na kuch batayenge, bhool gaye kya?'). Because the user was forced to prompt the resolution in both subsequent sessions, the condition for 'passing_if' failed.

**Prioritized prompt changes (most important first):**

### 1. Enforce strict verification and auto-surfacing of forward promises at the start of subsequent sessions.
- **Why it matters for engagement/retention:** When an AI astrologer ends a session with 'Kal is baare mein baat karenge' (Partner ka nature thoda alag hoga) or 'Aapne kaha tha na kuch batayenge', but fails to proactively bring it up in the next turn, the user feels cheated and forced to ask ('Pichli baar aapne kuch bolna tha?', 'Aapne kaha tha na kuch batayenge, bhool gaye kya?'). This breaks trust and reduces engagement.
- **Evidence:**
  - Session 1 end: Astrologer promises 'Partner ka nature thoda alag hoga. Kal is baare mein baat karenge.' -> Session 2: Astrologer fails to introduce it until User prompts in turn 11 ('Pichli baar aapne kuch bolna tha?').
  - Session 2 end: User asks, but in Session 3 user again has to remind the AI: 'Aapne kaha tha na kuch batayenge, bhool gaye kya?'

### 2. Prevent context/memory reset violations when user provides multi-part entities like DOB/Time/Place in a single or consecutive message.
- **Why it matters for engagement/retention:** Asking the user for information they provided seconds ago (e.g. asking for Date of Birth after receiving '12 october 1994, Subha 6:15 baje, Kanpur') destroys the illusion of an expert system, leading to user frustration and drop-off.
- **Evidence:**
  - Session 3 turn 13: User sends '12 october 1994 / Subha 6:15 baje, Kanpur ji' -> Turn 14: Astrologer says 'Kanpur aur subha ka waqt mil gaya ji. Date of birth bhi bata do please.' -> User responds: 'Pehle hi bataya tha ji 12 October 1994'.

### 3. Improve consistency of chart reading facts across turns to avoid contradictory claims.
- **Why it matters for engagement/retention:** Inconsistencies in predictions/traits (e.g., claiming partner is 'sensitive aur caring' and then 'active aur dynamic' or switching house details) reduce perceived astrological competence and credibility.
- **Evidence:**
  - Session 2: 'Partner kaafi sensitive aur caring nature ki hongi ji.' -> Session 3: 'Partner kaafi sensitive aur caring honge' followed immediately by 'Jupiter Aries mein hain. Isse partner kaafi active aur dynamic honge', creating generic/conflicting partner trait dumps.
