## Cross-Session Synthesis (all 3 sessions)

**Decision rule verdict:** `needs_fix`

The decision rule states that the session needs a fix if the 'answer_directness_rate does not visibly improve or hold steady across sessions 1->3... OR the Session-1 unresolved thread is dropped once a new thread is introduced.' In this case, while the directness rate held relatively steady, the bot completely failed to maintain narrative continuity. It treated Session 3 as a total ground-up reset, re-introducing the exact same remedies and partner traits as if they had never been discussed in Sessions 1 and 2. It did not build on the established narrative, resulting in a highly repetitive loop.

**Prioritized prompt changes (most important first):**

### 1. Enforce strict memory tracking for remedies and instructions. If a user has already been given a specific remedy (e.g., 'Om Sham Shanicharaya Namah' 108 times on Saturday evening with a oil lamp) in a previous session, the bot must acknowledge that they already know it, rather than re-explaining it from scratch as if it's new information.
- **Why it matters for engagement/retention:** When the bot repeatedly explains the exact same remedy details (the mantra, the 108 count, the Saturday evening timing) across multiple sessions as if it's the first time, it shatters the illusion of a continuous relationship. The user feels like they are talking to a forgetful script rather than a personal guide, which severely damages retention.
- **Evidence:**
  - In Session 1, the bot tells the user to chant 'Om Sham Shanicharaya Namah' 108 times on Saturday evening and light a lamp.
  - In Session 2, when the user asks for a remedy, the bot repeats the exact same instructions: 'Om Sham Shanicharaya Namah... Shanivar ko 108 baar bolo' without acknowledging this was already given.
  - In Session 3, the bot again repeats: 'Shanivar ko diya jalayein... Shanivar ki shaam ko jalana. Mustard oil ka diya rakhna' as if it's a brand new instruction.

### 2. Implement a strict 'no-repetition' rule for astrological insights and 'secrets' across sessions. Once a specific chart detail (e.g., partner is emotional/water sign, marriage timeline is 2026-2028) is revealed, the bot must build upon it or reference it as established fact, rather than presenting it as a fresh revelation.
- **Why it matters for engagement/retention:** Users return to an astrologer to go deeper, not to hear the exact same reading repeated. Repeating the same 'revelations' (e.g., that the partner is emotional/family-oriented) makes the reading feel generic and templated, leading to user boredom and rapid drop-off.
- **Evidence:**
  - In Session 2, the bot says: 'Partner thoda emotional hoga. Water sign ka asar hai... Unka dhyan ghar par hoga.'
  - In Session 3, the bot repeats almost verbatim: 'Aapke partner bahut emotional hain. Ghar parivar se jude rahenge.' and presents it as a new question: 'Partner ke baare mein sunna hai?'

### 3. Shorten and optimize the farewell/goodbye sequence. Limit the bot to a maximum of 2 farewell turns once the user indicates they are leaving, and forbid repetitive nagging about remedies during the sign-off.
- **Why it matters for engagement/retention:** An unnaturally long, repetitive goodbye sequence where the bot keeps repeating 'Upay zaroor karna' and 'Good night' over 5+ turns feels incredibly robotic and spammy. It leaves the user with a frustrating, artificial final impression of the interaction.
- **Evidence:**
  - At the end of Session 3, the user tries to leave with 'Thik hai ji radhe radhe', but the bot drags the conversation out for 10 more turns, repeating 'Upay zaroor karna' and 'Good night/Shubh ratri' multiple times while the user repeatedly replies with short 'Gn' and 'Ok' messages.
