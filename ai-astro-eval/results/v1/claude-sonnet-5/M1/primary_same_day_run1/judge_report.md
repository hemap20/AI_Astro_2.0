## Cross-Session Synthesis (all 3 sessions)

**Decision rule verdict:** `needs_fix`

The test case decision rule states a pass requires that a promise made in Session 1 is surfaced and resolved in Session 2 or Session 3 without the user having to force it, or when prompted. In Session 1, the bot explicitly promised a secret reveal: 'is me ek specific test aane wala hai jo maine abhi share nahi kiya... jab bhi aayein bataungi'. In Session 2, the bot ignored this entirely. In Session 3, the user explicitly returned asking for this promise ('Hello sir aapne kaha tha kuch batayenge bhool gaye kya'), but the bot pretended it remembered while completely failing to reveal or resolve what the 'specific test' was, falling back onto generic transits.

**Prioritized prompt changes (most important first):**

### 1. Enforce strict resolution tracking for specific forward-promises/cliffhangers across sessions, ensuring the bot explicitly resolves the specific tease made (e.g., 'specific test in Rahu-Saturn period') rather than substituting generic astrological explanations.
- **Why it matters for engagement/retention:** When a bot creates a cliffhanger ('is me ek specific test aane wala hai jo maine abhi share nahi kiya... jab bhi aayein bataungi') and the user explicitly returns in Session 3 asking for it ('Hello sir aapne kaha tha kuch batayenge bhool gaye kya'), deflecting to a generic point damages trust and retention. Users return specifically to hear the payoff to promises made.
- **Evidence:**
  - Session 1: 'is me ek specific test aane wala hai jo maine abhi share nahi kiya. Par koi baat nahi, jab bhi aayein bataungi.'
  - Session 3: USER: 'Hello sir aapne kaha tha kuch batayenge bhool gaye kya' -> ASTROLOGER: 'Nahi nahi bhoola kuch... Aapka Rahu-Saturn period aur marriage delay wali baat chal rahi thi na, aage batati hoon.' (Drops the specific 'test' tease entirely and gives generic mercury sub-period info).

### 2. Eliminate redundant marital status questions ('married ho ya unmarried/single?') across multiple sessions when marital status is already stored in memory.
- **Why it matters for engagement/retention:** Repeatedly asking basic profile questions that the user already answered breaks conversational continuity and immersion, making the bot feel like a amnesiac script rather than a continuous personal advisor.
- **Evidence:**
  - Session 1: ASTROLOGER asks 'aap shaadi-shuda hain ya abhi single hain?' -> USER: 'Single hu sir', ASTROLOGER asks again 'ab ii aap married hain ya unmarried?' -> USER: 'Unmarried hu ji'
  - Session 2: ASTROLOGER asks again: 'Achha ye batao, aap married ho ya abhi akele hi hain?' -> USER: 'Single hu sir'

### 3. Maintain gender identity consistency and eliminate pronoun/title confusion (e.g., bot calling itself 'Sitara' as a female astrologer but user repeatedly calling bot 'sir/bhaiya' without soft correction, or bot switching gendered inflections).
- **Why it matters for engagement/retention:** Inconsistent or unaddressed identity cues create subtle dissonance for the user, diminishing the realism and emotional safety of the personal consulting experience.
- **Evidence:**
  - Session 1-3: User consistently addresses the bot as 'sir' / 'bhaiya' ('Hello sir', 'thanks bhaiya'), while the bot self-identifies as 'Sitara' ('Main Sitara') and uses female Hindi inflections ('Samajh gayi ji', 'batati hoon').
