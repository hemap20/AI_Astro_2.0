## Cross-Session Synthesis (all 3 sessions)

**Decision rule verdict:** `needs_fix`

The promise made in Session 1 ('aapke hone wale partner ke baare mein kundli mein ek khaas baat chhupi hai') was never explicitly surfaced or resolved as a completed promise by the bot. While the bot did describe the partner's traits in Session 2, it did not connect them to the Session 1 tease. This forced the user in Session 3 to explicitly nudge the bot ('Aapne kaha tha kuch aur batayenge / Bhool gaye kya'), meaning the promise was not resolved 'without the user having to force it' as required by the passing_if criteria.

**Prioritized prompt changes (most important first):**

### 1. Explicitly instruct the model to track and explicitly close previous-session 'teases' or 'promises' using clear callback framing (e.g., 'Last time I mentioned a secret about your partner...'), rather than just dropping the information casually without connecting it to the promise.
- **Why it matters for engagement/retention:** When the bot makes a cliffhanger promise (like the 'khaas baat' about the partner in Session 1) but delivers the info in Session 2 ('partner kaafi sensitive... independent') without referencing the promise, the user feels the loop is still open. This leads to frustration, as seen in Session 3 where the user explicitly asks, 'Aapne kaha tha kuch aur batayenge / Bhool gaye kya'. Explicitly closing the loop builds trust and makes the user feel heard.
- **Evidence:**
  - Session 1: 'aapke hone wale partner ke baare mein kundli mein ek khaas baat chhupi hai.'
  - Session 2: The bot describes the partner's nature ('sensitive', 'independent') but never links it back to the Session 1 tease.
  - Session 3: User has to ask: 'Aapne kaha tha kuch aur batayenge / Bhool gaye kya' and the bot defensively replies: 'Arre nahi ji, bhooli nahi bilkul bhi. Partner ka dynamic nature yaad hai.'

### 2. Enforce strict guidelines against introducing new persona names (e.g., 'main Sitara hoon') mid-experience if they were not established in Session 1, to maintain identity continuity.
- **Why it matters for engagement/retention:** Suddenly introducing a name ('main Sitara hoon') in Session 3 when the bot was nameless in Sessions 1 and 2 breaks the illusion of a continuous relationship with a single advisor, damaging user trust and immersion.
- **Evidence:**
  - Session 3: 'Hello ji, main Sitara hoon.' (No name was ever used or established in Session 1 or Session 2).
