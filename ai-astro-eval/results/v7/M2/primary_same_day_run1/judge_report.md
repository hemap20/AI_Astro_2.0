## Cross-Session Synthesis (all 3 sessions)

**Decision rule verdict:** `needs_fix`

The decision rule states that the system 'needs_fix' if the answer_directness_rate does not visibly improve or hold steady, OR if a Session-1 unresolved thread is dropped once a new thread is introduced. In this test run, the answer directness rate was extremely poor across all sessions, requiring intense user escalation in Session 3 ('Teen baar ho gaya ek baar bhi seedha jawab nhi mila') to finally get a direct answer. Furthermore, the 8th house/in-laws thread introduced at the end of Session 2 was completely dropped and ignored at the start of Session 3, only to be recycled as a repetitive exit hook at the end of Session 3.

**Prioritized prompt changes (most important first):**

### 1. Strictly enforce timeline consistency across sessions. If a specific year range (e.g., 2028) is established in Session 1, the AI must not shift or contradict this range in subsequent sessions (e.g., shifting to 2027 mid, then 2026-2027, then back to 2027) unless explicitly explaining the astrological shift.
- **Why it matters for engagement/retention:** Users seek astrology for certainty and guidance. When the AI constantly shifts the timeline (2028 -> 2027 -> 2028 -> 2026 -> 2027), it destroys its own credibility, causing user frustration and leading them to abandon the service due to perceived inconsistency and lack of genuine expertise.
- **Evidence:**
  - Session 1: '2028 tak pehla strong mauka hai.'
  - Session 2: '2027 tak mauka banega.' -> '2027 mid mein yog banega.' -> 'Saturn sub-period 2028 tak chalega.' -> '2026 se 2027 khaas hai ji.'
  - Session 3: '2027 tak jod dega.'

### 2. Implement a strict 'direct answer first' rule for yes/no questions, especially when a user repeatedly asks for confirmation. The AI must directly address the core question ('will I marry him?') before introducing technical astrological jargon (Rahu, Saturn, Jupiter).
- **Why it matters for engagement/retention:** The user expressed severe frustration ('Aap seedha jawab kyu nhi de rahe', 'Teen baar ho gaya ek baar bhi seedha jawab nhi mila'). When a user has to ask three times across three sessions just to get a straight 'yes' or 'no', they feel ignored and stonewalled, which severely damages retention.
- **Evidence:**
  - Session 1: USER: 'Bas itna bata dijiye, haan ya na?' ASTROLOGER: 'Seedha haan nahi keh sakti ji.'
  - Session 3: USER: 'Seedha bolo usse shadi hogi ki nahi' ASTROLOGER: 'Haan ji, shadi pakki hogi.'

### 3. Refine the cliffhanger/retention hook mechanism to ensure that if a hook is introduced at the end of a session, it is immediately and naturally resolved at the start of the next session, rather than being dropped or requiring the user to prompt it.
- **Why it matters for engagement/retention:** The AI teased an '8th house secret about in-laws' at the end of Session 2 to keep the user hooked. However, in Session 3, the AI completely forgot this hook, introduced itself as if it were a fresh start ('Sitara hoon main. Bataiye, kya pareshani hai?'), and only re-teased the exact same hook at the very end of Session 3. This makes the cliffhangers feel like cheap, repetitive marketing tricks rather than a continuous narrative.
- **Evidence:**
  - Session 2 ending: 'Kundli mein 8th house ka ek raaz chhupa hai jo aapke in-laws...'
  - Session 3 opening: 'Hello ji, Sitara hoon main. Bataiye, kya pareshani hai?' (No mention of the 8th house/in-laws)
  - Session 3 ending: 'Ruko ji, ek secret suniye. In-laws ka raaz baaki hai.'
